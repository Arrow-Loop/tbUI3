# S3 icon glyph and system-font specification

Status: 1.0.0.3 implementation candidate packed 2026-10-06; awaiting BETA 997 compile/runtime validation.

## Fidelity correction

This S3 spec is governed by `CONTROL_FIDELITY_POLICY.md`.

The 1.0.0.3 candidate exposed an important distinction:

- WinUI `Button` itself does **not** define `Icon`, `IconPosition`, or `IconSpacing` properties. Its template exposes arbitrary `Content`.
- Therefore tbUI3's `Icon`, `IconGlyph`, `IconFontName`, `IconPosition`, and `IconSpacing` are **VB/twinBASIC convenience abstractions over Button.Content**, not WinUI Button properties.
- Their existence is acceptable because they make common icon+text composition practical in a property-grid workflow, but their defaults must not be presented as exact Button XAML values unless Button-specific source defines them.
- The semantic glyph table and the 20-DIP SymbolIcon core size are source-derived WinUI facts.
- The current 8-DIP `IconSpacing` default comes from general WinUI Gallery spacing guidance, not Button-specific XAML. Treat it as a tbUI3 convenience default, not “the WinUI Button spacing.”

Do not validate 1.0.0.3 as an exact Button implementation until its per-control source matrix distinguishes these source-derived facts from convenience API choices.

## Goal

Add native WinUI-style icon glyph support to tbUI3 without bundling fonts and without adding another package dependency.

S3 has two immediate jobs:

1. give controls a reusable DirectWrite icon-glyph path, beginning with UI3Button;
2. finish the text-font fallback proof already started in S2: Segoe UI Variable Text when present, Segoe UI otherwise.

This is not the full `UI3Image` / IconElement implementation. BitmapIcon, ImageIcon, PathIcon and AnimatedIcon coverage belong to the later control-surface work in `CONTROL_INVENTORY.md`.

## Font-family rule

Use installed Windows fonts only.

For ordinary control text:

1. `Segoe UI Variable Text` when DirectWrite reports that family installed;
2. `Segoe UI` otherwise.

For system glyph icons:

1. `Segoe Fluent Icons` when installed;
2. `Segoe MDL2 Assets` otherwise.

Do not bundle or redistribute Microsoft font files.

The current `UI3Direct2D.FontFamilyExists` helper already provides the correct DirectWrite-based family probe and should remain the common detection path.

## Critical glyph-mapping rule

Do **not** assume the same Unicode code point maps to the same semantic icon in Segoe Fluent Icons and Segoe MDL2 Assets.

Microsoft's current `symbol-enum-spec.md` explicitly maps many old/legacy code points to different Fluent code points. Examples:

| Symbol | MDL2 / legacy | Segoe Fluent Icons |
| --- | ---: | ---: |
| Accept | E10B | E8FB |
| Add | E109 | E710 |
| Back | E112 | E72B |
| Calendar | E163 | E787 |
| Camera | E114 | E722 |
| Cancel | E10A | E711 |
| Delete | E107 | E74D |
| Edit | E104 | E70F |
| Home | E10F | E80F |
| Save | E105 | E74E |
| Setting | E115 | E713 |

Therefore tbUI3's built-in semantic icon table must store **both** the MDL2 and Fluent glyph for every named symbol whose mapping differs.

## Public API direction

The common public icon contract should be shared by any control that can naturally show an icon.

### Semantic icon property

Provide a package enum such as `UI3Icon` with `ui3IconNone` plus named Microsoft-compatible semantic symbols.

A semantic enum is preferred over requiring a raw PUA character because:

- the IDE property pane can show meaningful names;
- tbUI3 can select the correct Fluent or MDL2 code point automatically;
- users do not need to know which Windows icon font is installed;
- the same saved form remains correct across Windows 10 and Windows 11.

The initial enum should be generated from Microsoft's current Symbol mapping rather than hand-entered piecemeal. Keep a source comment identifying the upstream Symbol table snapshot.

### Raw glyph escape hatch

Also plan an advanced raw glyph path for icons outside the semantic table:

- `IconGlyph` string;
- optional `IconFontName` override.

When `IconGlyph` is explicitly supplied, it is the caller's responsibility to provide a glyph valid for the selected font. The semantic `Icon` property remains the portable path.

Exact precedence before release:

1. explicit image/path content when a later control supports it;
2. explicit `IconGlyph`;
3. semantic `Icon`;
4. no icon.

Do not expose a dozen mutually exclusive public icon properties without clear precedence.

## UI3Button S3 surface

S3 should add icon support to the existing UI3Button without turning button variants into separate toolbox controls.

Planned properties:

- `Icon As UI3Icon`, default None;
- `IconGlyph As String`, default empty;
- `IconPosition As UI3IconPosition`, default Left;
- `IconSpacing As Single`, a tbUI3 convenience property because WinUI Button accepts arbitrary Content rather than defining an icon gap.

The button's existing `Caption` remains the VB-style text/content property.

The S3 implementation must support at least:

- text only;
- icon only;
- icon + text;
- design-time and runtime rendering;
- Standard and Accent S2 styles.

Do not implement Toggle/Split/DropDown/Repeat behavior during S3 merely because those families will eventually reuse icons.

## Button style correction discovered during the audit

The current WinUI Gallery Button page demonstrates both `AccentButtonStyle` and `SubtleButtonStyle`.

Therefore `UI3Button`'s final family coverage includes **Subtle** in addition to Standard and Accent. S3 need not implement the Subtle visual state if doing so would mix S7 styling work into the icon pass, but the control inventory and future enum must reserve it.

## DirectWrite implementation design

The current `UI3Direct2D` module has one cached `ControlTextFormat` and a `DrawCenteredText` helper.

S3 should refactor that narrowly rather than duplicate the renderer:

- retain `ControlTextFormat` for normal control text;
- add a cached icon text format using the selected system icon font;
- add a generic private helper that can create a text format for a supplied family/size/alignment;
- keep DirectWrite factory/interface declarations private to the package.

### Measuring icon + text

Do not position icon+caption content with guessed fixed offsets.

For WinUI-like centering, the combined icon + spacing + caption block needs its actual width. Add only the minimum DirectWrite text-layout/metrics interface slots required to measure glyph and caption runs, preserving the current vtable-slot discipline in `UI3Direct2D.twin`.

The combined content block should be centered as a unit, with the icon and caption individually vertically centered.

## Font-size and resource discipline

Do not invent a universal icon size.

Different WinUI controls use different icon sizes (for example command-bar/split-button glyphs differ from ordinary content icons). Each family should source its size from the corresponding microsoft-ui-xaml template/resource.

For UI3Button S3, the implemented semantic SymbolIcon size is 20 DIPs from microsoft-ui-xaml's IconElement/SymbolIcon core default (`g_ClientCoreFontSize = 20.f`). Button content is arbitrary XAML and has no Button-specific icon-gap resource. The current 8-DIP `IconSpacing` default is therefore a **tbUI3 convenience choice** borrowed from general WinUI Gallery spacing guidance; it must not be described as the WinUI Button spacing.

## Directionality

Left/right icon placement must respect the control's effective right-to-left behavior once RTL support is implemented.

Do not bake English-only left-to-right assumptions into the drawing helper.

## Accessibility

An icon used only as decoration should not create a second accessible name.

An icon-only interactive control must expose an accessible name through the control's eventual accessibility contract. S3 can draw the glyph before UI Automation is complete, but the missing accessibility behavior must remain tracked rather than being mistaken for finished icon-button support.

## Validation

After implementation, validate:

1. design-time and runtime glyph rendering in win32;
2. runtime glyph rendering in win64;
3. semantic icon resolves to Segoe Fluent Icons on Windows 11;
4. forced/fallback path resolves to Segoe MDL2 Assets using the **matching legacy code point**, not the Fluent code point;
5. ordinary caption text still uses Segoe UI Variable Text when available;
6. ordinary caption text falls back to Segoe UI when Variable Text is unavailable/forced off for the test;
7. icon-only, text-only and icon+text buttons remain centered at normal and enlarged control sizes;
8. Standard and Accent styles remain visually unchanged when no icon is configured;
9. package still coexists with the reference packages without name collisions.

A test-only internal override may be used to force the fallback families so Shane does not need to uninstall Windows fonts. Do not expose that override as a production public property.

## Out of scope for S3

- BitmapIcon/ImageIcon/PathIcon/AnimatedIcon as complete public objects;
- hover/pressed/disabled button visuals (S7);
- keyboard/default/cancel behavior (S8);
- windowless/transparency (S4);
- Mica (S5);
- per-monitor DPI (S6);
- full UI Automation provider implementation.

S3 should leave those roadmap boundaries intact.

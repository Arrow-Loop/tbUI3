## Implementation and sources

The screenshot showed blue native title/menu bars against the inset neutral main window. The generated Light theme explicitly set MenuBackColor #005FB8 and white text; it now uses SolidBackgroundFillColorBase #F3F3F3 and dark text. Additional styling supplies the same neutral body variables even when an older theme file is installed, and fixes native white title text/minimize-maximize PNGs. The Close codicon stays dark on neutral hover. Dark chrome remains unchanged.

Windows palette source is the documented [UISettings.GetColorValue](https://learn.microsoft.com/en-us/uwp/api/windows.ui.viewmanagement.uisettings.getcolorvalue), with [UIColorType](https://learn.microsoft.com/en-us/uwp/api/windows.ui.viewmanagement.uicolortype) shades 8 through 2. The minimal private IID/slot layout follows Microsoft's [WPF UISettingsRCW](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/MS/internal/WindowsRuntime/Windows/UI/ViewManagement/UISettingsRcw.cs) and the Windows SDK ABI. No WinRT/WinDevLib package is imported. Fill/link mapping follows Microsoft's [Common_themeresources_any.xaml](https://github.com/microsoft/microsoft-ui-xaml/blob/main/controls/dev/CommonStyles/Common_themeresources_any.xaml): dark fill Light2/link Light3, light fill Dark1/link Dark2; hover/pressed retain 90%/80% fill opacity. Other mapped native accents retain their existing resource roles. Main-window neutral composition is Shane's requested policy.

The native bridge polls while the selected theme is one of the exact two WinUI names and styling is On. The page rechecks eligibility on every sync and immediately on styling option changes. A separate owned stylesheet overrides body resources without mutating activeThemeData/root inline palette; Off, theme departure and unload remove it. Failed/invalid palettes remove overrides and leave static fallbacks. HSTRING, COM and apartment lifetime are balanced. Package/control identities and adapter v8 are unchanged.

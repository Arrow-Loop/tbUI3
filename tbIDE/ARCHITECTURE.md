# tbUI3IDE architecture

## Distribution and identity

One canonical project, tbUI3IDE/tbUI3IDE.twinproj, produces tbUI3IDE.dll per IDE architecture, version 1.3.0.1. Its established project ID is unchanged. Remove legacy WinUI3IdeStyle.dll and TabViewDesigner.dll from both addins architecture directories during migration. Theme files and the tbUI3 runtime control package remain separate; built consumer applications do not need this add-in.

## Entry point and independent features

MainModule exports the single tbCreateCompilerAddin and returns tbUI3IDEAddin. It starts TabViewDesignerController independently of theme/layout preferences. The controller and adapter v8 retain native page editing, locks, hidden toolbox entry, host targeting, creation/deletion/reordering and lifecycle cleanup.

The hidden tbUI3IDE tool window reaches the existing IDE document through ownerDocument.defaultView.eval. MainModule installs IdeToolbarScript for every theme, then separately applies WinUI3IdeCss only for the included WinUI3 theme names. The existing WinUI3IdeStyle/Options/Enabled setting is intentionally retained. The new ToolbarMode value in that same namespace is independent; Classic is the default when absent. The shared options timer persists both preferences independently and reports toolbar fallback errors. The settings observer exposes the additional-styling row on every theme so the toolbar combo can remain immediately below it.

## Live command adapter and presentation

js/ide-toolbar.js owns the three toolbar renderers and their essential CSS lifecycle. Classic preserves the native surface. Hybrid retains native menus and groups existing toolbar commands in Home/Code/Form/contextual MultiPage/Add-ins. Ribbon discovers the native rootMenu1Inner headers and captures their showContextMenu descriptors without executing command actions. The pure js/ribbon-layout.js factory classifies these current descriptors into task-based tabs/groups, uses js/ribbon-presentation.js to apply function-based large-button roles (never group position) and builds compact dropdown wrappers. Known IDs/localization tokens guide grouping; unknown commands/menus retain fallback destinations. See RIBBON_LAYOUT.md for the exact mapping. Lazy submenus remain demand-driven. It preserves command IDs, alternatives, native context expressions, enabled/checked states, combo options and original actions. Native toolbar command proxies dispatch the ordinary mouse sequence to the original nodes; build/zoom/grid controls retain their original nodes and handlers.

The live adapter observes current sources through a bounded 400ms scan, captures the active menu no more than once per second, and reconciles late toolbar/menu contributions without a whitelist of future commands. It supports synchronous/lazy submenus and the native asynchronous Add-ins list. Unsupported native structure restores Classic while retaining the requested mode for persistence. Private-API structural compatibility is not guaranteed for arbitrary future betas.

The fullscreen File view sits inside the IDE window. File uses a vertical rail and vertical task lists backed by native descriptors. Info shows the actual project name with settings/references tasks. Native Help now resides under File > Help; native Help menu opening is intercepted to this page. Options, Save and Exit restore/close Backstage before native dispatch; language/keyboard schemes live under Preferences. The workspace/designer and floating panels are hidden/inert with their previous accessibility values restored on close, action, mode change or unload. Stable signatures retain focus across refreshes. Loaded-add-in information moves into its Add-ins section; other add-ins' toolbar contributions remain on the Add-ins ribbon tab. BETA 1044 has no functional native enable/disable action: its loaded-add-in actions call notSupportedMenuOption. Those entries are displayed disabled with an explanation, and real enablement remains roadmap work.

Save/Undo/Redo/Play/Pause/Stop use the former menu space in rootMenu1Inner, which is the custom title bar when Show real OS titlebar is off and the row above the ribbon when it is on. Window controls and title-drag handlers remain owned by the IDE. File Escape/back returns focus; tab arrow navigation and Ctrl+F1 collapse are handled locally. Undo/Redo and the three main execution controls are omitted from content groups. Current groups use explicit large command roles and three stacked rows with horizontal overflow; complete Office adaptive collapse/keytips and visual acceptance remain open.

The 1.2.0.1 geometry uses central CSS variables: command area 100px maximum and separate tab strip 26px maximum; full-size button minimum/standard width 50px, maximum width 86px and fixed height 76px. Border-box sizing includes padding/borders. Three stacked 24px rows with two 2px gaps also occupy 76px. Compact group captions and two-line large-button labels keep that vertical budget; complete captions remain in tooltips. Quick-access, Backstage and popup controls retain their own dimensions. These are Shane's explicit composition values, supported by his Office spacing screenshot, rather than asserted WinUI Ribbon template values.

The 1.2.0.2 presentation separates short known-command/selector captions from full native help/shortcut tooltips. This mapping only refines labels; discovery and dispatch remain native and unknown contributions remain accessible. Stacked captions use single-line ellipsis, and group padding/column gaps are compact. Essential toolbar CSS carries the existing simplified-toolbar Fluent shadow4 elevation and 8px card corners; it does not substitute a new theme palette.

## Theme and icon ownership

css/ide-toolbar.css is essential presentation, independent of the optional theme stylesheet. Surface/foreground colors follow the active IDE theme, including standard and third-party themes. The toolbar uses the existing color-card / CardBackgroundFillColorDefault token when available, otherwise themeToolbarBackground; foreground follows color-text / themeGeneralTextColor. Quick access retains the menu/titlebar foreground, and popups use their native context-menu surface/foreground. Essential light/dark SubtleFillColorSecondary/Tertiary alpha fills use the same pinned WinUI resources as winui3-ide.css, independently of the optional styling switch; these are interaction effects rather than a replacement palette. WinUI 3 supplies the visual language; Office supplies the ribbon organization. The existing 19 Fluent SVGs are scaled to 28px full-size / 18px stacked presentations. icons/ribbon.json adds 17 MIT Fluent SVGs from pinned Microsoft source for missing glyphs; the builder embeds them into the same masked-currentColor map. Native codicons and original source images take priority where established. Text-only add-ins/future commands get a Fluent fallback instead of an empty or hidden icon. Native designer glyphs and other add-ins' images are retained. No Office icons or additional runtime icon-library dependency is introduced.

WinUI3IdeCss and its 288 generated rules remain unchanged. Its media state and panel-title normalization are controlled solely by the original additional-styling switch. No toolbar renderer reads that switch or requires an included theme name.

The grid options retain native nodes/events but use the ribbon foreground, themed number-input fill/border and a two-column, three-row layout. Large-button dropdown chevrons are positioned within the fixed button box so they do not consume an additional row.

## Packaging and cleanup

tools/build-ide-toolbar.mjs embeds the readable adapter, essential CSS, command presentation metadata and the combined Fluent map into IdeToolbarScript.twin. tools/build-tabview-designer.mjs embeds the page adapter and patches all current sources/Settings into the canonical project. The .meta project-root rename is applied explicitly. Loose JS/CSS remain review inputs, not runtime dependencies. Source mirrors are compared against packed entries and the current official exporter.

Mode change/unload removes owned surfaces and restores native selectors/grid nodes from comment markers, native menu visibility, the docked toolbar header, its exclusive dock/floating slot and the original showContextMenu hook when still owned. Cleanup preserves wrappers installed later by other add-ins. The adapter reconciles its hidden-node set after redocking. A dock/floating slot is hidden only when its sole sectionHeader is the TOOLBAR header, so shared native panels are retained; no saved layout dimensions are rewritten. The options timer stops and both feature lifecycles dispose. Pending theme/toolbar preferences are drained before teardown. See ROADMAP.md and ../docs/validation/2026-11-10-ide-toolbar.md for remaining acceptance boundaries.

# tbUI3IDE architecture

The unified add-in includes native TabView management, optional WinUI styling, toolbar modes, update coordination and offline resource provisioning. The accepted Win32 updater and both themes are embedded in the canonical DLL project. See [installation contracts](INSTALLATION_CONTRACTS.md) for the native services and [Phase 1 acceptance](PHASE1_HANDOFF.md) for current validation. Build uses the single embedded buildv3.svg asset; Quick Access includes Build between Redo and Play. Full Ribbon/Hybrid uses 7px top padding and a 73px command area within the 100px card; Simplified and Quick Access retain their own geometry.

## Update ownership boundary

Updater.exe owns automatic checks, its standalone notification and review, installation-specific preferences, consent, progress and recovery. The add-in keeps the Welcome Wizard, offline provisioning/repair and the IDE entry points. Its native bridge acknowledges the IDE's accepted save or discard before compiler teardown. Apply combines that acknowledgement with the sealed verified plan after staging, process exit and lock checks. The [implementation contract](INSTALLATION_CONTRACTS.md#session-and-approval) defines the records and trust boundaries.

## Distribution and identity

One canonical project, tbUI3IDE/tbUI3IDE.twinproj, produces tbUI3IDE.dll per IDE architecture, current source version 0.4.0.0. Its established project ID is unchanged. Remove legacy WinUI3IdeStyle.dll and TabViewDesigner.dll from both addins architecture directories during migration. Theme files and the tbUI3 runtime control package remain separate; built consumer applications do not need this add-in.

TabView adapter v10 supports the current package's Edge/Explorer shape profiles, reserved curve space, right-hand add button and overflow arrows. Viewport scrolling uses the transient native FirstVisibleTabIndex and queued parent snapshots, preserving page selection/ownership. Ribbon/theme/document-command behavior from the previous pass is retained. Rebuild/re-import the package and rebuild/reload the add-in together; native acceptance remains pending.

Save Document follows the selected code/form document's dirty and read-only state. It uses the IDE's native per-editor writer, preserving its completion/failure behavior and leaving other dirty documents alone. A project without a saved path first opens native Save As. Form / Code enables only when the selected document has a matching designer/code file; standalone modules disable it. Both commands use the same behavior in Ribbon/Hybrid, full/simplified.

The ribbon card's shadow and bottom border apply only to WinUI3 Dark/Light. Standard and third-party themes use a flat command surface in both Ribbon and Hybrid, full and simplified. Live theme changes preserve command/control nodes. This presentation choice is independent of additional styling; other layout and interaction behavior is unchanged.

Simplified Grid's toggle/flyout composition groups the original source proxy and a separate dialog arrow. The native options body is parked inside a shared fieldset and hidden holder; opening uses the same top-layer popup helper as command dropdowns and reparents the fieldset, not cloned inputs. Closing first returns the fieldset to its holder; tab/mode/unload cleanup then restores the body to the native marker. Native input handlers/values and toggle state remain authoritative. Arrow availability follows form context/source disabled state. The original Show Grid row is visually hidden because the main toggle replaces it. Shared fieldset CSS supplies popup rows/fields, including the established exception to native white !important. Menu hydration defers rendering while Grid edits are open; normal tab/selection/mode/context cleanup remains active. This is an HTML composition, not a new runtime WinUI ToggleSplitButton dependency. The corner toggle overlays the card with reserved end padding, compact rows are centered, and Quick Access has 16px internal left padding.

Ribbon and Hybrid share an independently saved full/simplified presentation flag. The same DOM controls and callbacks are styled as full three-row groups or a compact single row; no descriptors are discarded or duplicated by switching. A fixed accessible corner toggle exposes pressed/expanded state and a down/up chevron. CSS changes the command-area budget from 100px to 48px, retains the 26px tabs, hides only visual group captions, and leaves long rows horizontally scrollable. Wheel handling excludes native inputs/selectors; focusin reveals off-screen controls. Popups close before geometry changes. setSimplified restores this presentation without marking it dirty; user changes set simplifiedDirty. MainModule restores/saves the separate SimplifiedRibbon key and drains toolbar, simplified and styling flags separately before teardown. Mode changes retain the preference and apply it to both replacement profiles. Ctrl+F1 switches full/simplified in both; Hybrid retains its smaller inventory and native menus without Quick Access or Backstage. Native compiled-host acceptance and adaptive group overflow/keytips remain open.

Explicit icon references in ribbon-presentation.js override native glyphs/backgrounds only for Shane's named commands. Segoe references use the installed Windows font; Fluent references resolve to embedded SVGs in icons/requested.json, pinned to @fluentui/svg-icons 1.1.341 with per-asset hashes and a documented Page Right derivative. Unlisted commands retain native/fallback artwork. Build-time import is separate from offline script generation. No icon package or extra image file is required at runtime. Save Document retains tbEditor_Save as its presentation identity in the leading Code/Form Document group, but uses the add-in document bridge to openEditors.save(selectedNode), since BETA 1044 explicitly disables the native menu command; Ribbon removes it from File, while Hybrid's native menus remain authoritative. MultiPage's six native proxies form three pairs with vertical separators inside the contextual group after Grid.

The centralized TabView eligibility monitor reads the active project’s applied Settings through the IDE file service and checks the compiler’s resolved control list for the active consumer form. Both the package GUID and stable TabView and TabPage classes must match. The gate discards late file responses and stale compiler lists on a project switch and expires unavailable settings. The designer adapter is disposed when the form or its eligibility changes. Disposal restores its locks, visibility overrides, listeners and snapshot hook. Classic and the replacement toolbars use the same contextual selection result, and native button dispatch checks it again before running an operation.

In both Ribbon and Hybrid, full layouts retain the requested secondary labels and inline Grid options. Only Simplified hides the Center in Container, Lock Controls, Preview, Grid, Page Left/Right, TabView Refresh/Diagnostics and Insert Folder/Other file/Import labels and puts Grid options in a toggle-split flyout. Help, accessible names, original values and events remain. The original ten alignment/size commands stay icon-only in both presentations. The chevron sits inside both cards with a transparent resting background and hover fill; its glyph remains visible. Simplified controls are vertically centered. Quick Access retains 16px internal left padding.

Both replacement profiles support full/simplified presentation using the corner chevron or Ctrl+F1 and the same independently saved preference. Hybrid retains native menus, its smaller Home/Code/Form/Add-ins inventory and no Quick Access or Backstage. No fourth toolbar mode is added.

Save Document and Form / Code share the leading Document group in Code and Form, in that order, for both profiles. The latter dispatches the native Switch Between Form and Code action with its native tooltip. Classic retains its original native toolbar inventory/order/handlers while showing the corresponding Ribbon glyphs and tooltips without button labels; selectors retain their native display.

Only in WinUI3 Dark/Light with additional styling enabled, main-window surfaces receive 8px side insets and no bottom inset. An 8px top inset applies only with the real OS titlebar disabled. The caption/Quick Access row is excluded from side insets, retaining Quick Access padding and native caption-button geometry.

The inset lifecycle records/restores root classes and CSS variables. Caption-row sizing uses the measured border-box height and original inner offset to avoid shifting native caption buttons. Disposing removes insets and requests native resize. The optional stylesheet now has 290 generated rules; essential scoped CSS supplies these geometry rules. Native compiled-host acceptance remains pending.

WinUI3 Light uses neutral #F3F3F3 window/menu chrome. Optional styling fixes the IDE's native white caption text/icons and normalizes older installed Light theme chrome. Both WinUI3 themes use the current Windows accent palette while additional styling is enabled. The existing one-second options timer reads Windows.UI.ViewManagement.UISettings; theme changes, styling Off and unload remove the accent overrides. Static themes remain usable independently with fallback blue accents.

The builder embeds js/system-accent.js beside the toolbar. MainModule contains a private, minimal IUISettings3 ABI definition and Windows Runtime activation helpers; there is no new package dependency or public API. ReadPalette balances successful RoInitialize calls with RoUninitialize, releases COM objects, deletes the HSTRING on success/failure and returns null for unavailable colors. The UISettings four-byte Color retval is read as a Long and its A/R/G/B bytes converted explicitly to CSS RGB. An x86/x64 C# ABI probe validates the same native signatures and channel conversion; this does not replace a twinBASIC build.

The appearance module owns only a scoped body stylesheet. It never edits activeThemeData or the native root inline palette, avoiding conflict with the theme-transition observer's restoration logic. Enabled/name eligibility is checked on both polling and option changes. Native accent properties and --color-accent/link/hover/pressed consume the system shades; progress bars consume --color-accent. Static tokens remain fallback resources when Windows reads fail. Only the exact two WinUI names qualify, with case normalized.

The document bridge in js/native-toolbar-context.js checks native project state, editor type, writability and isDirtyEditor. Generated execute/commandEnabled callbacks intercept only tbEditor_Save; other commands retain native dispatch/context evaluation. Native code/form file handlers own serialization, version numbers, write completion, tab spinner and dirty state. For Save As, the bridge captures the original node and verifies fileNode.openEditorNode identity before saving; it does not redirect to a later selected editor. No global ideCommands entries are patched.

Form/Code proxy state combines the original native disabled state with a counterpart lookup matching toggleFormDesign/switchToFormPart/switchToCodePart. A live check precedes original source mouse dispatch, so a stale enabled button cannot invoke the native not-part-of-form warning. The original Classic source remains native-owned.

## Entry point and independent features

MainModule exports the single tbCreateCompilerAddin and returns tbUI3IDEAddin. It starts TabViewDesignerController independently of theme/layout preferences. The controller and adapter v8 retain native page editing, locks, hidden toolbox entry, host targeting, creation/deletion/reordering and lifecycle cleanup.

The hidden tbUI3IDE tool window reaches the existing IDE document through ownerDocument.defaultView.eval. MainModule installs IdeToolbarScript for every theme, then separately applies WinUI3IdeCss only for the included WinUI3 theme names. The existing WinUI3IdeStyle/Options/Enabled setting is intentionally retained. The new ToolbarMode value in that same namespace is independent; Classic is the default when absent. The shared options timer persists both preferences independently and reports toolbar fallback errors. The settings observer exposes the additional-styling row on every theme so the toolbar combo can remain immediately below it.

## Live command adapter and presentation

js/ide-toolbar.js owns the three toolbar renderers and their essential CSS lifecycle. Classic preserves native control identity/order/handlers while reversibly wrapping original child content and adding the same icon resolver used by Ribbon. Native button text is visually hidden; original help and accessible names remain. The scan reconciles late contributions and restores original contents when leaving Classic or disposing. Scoped native-paint overrides suppress original backgrounds/pseudo-icons without changing selectors. Hybrid retains native menus and groups existing toolbar commands in Home/Code/Form/contextual MultiPage/Add-ins. Ribbon discovers the native rootMenu1Inner headers and captures their showContextMenu descriptors without executing command actions. The pure js/ribbon-layout.js factory classifies these current descriptors into task-based tabs/groups, uses js/ribbon-presentation.js to apply function-based large-button roles (never group position) and builds compact dropdown wrappers. Known IDs/localization tokens guide grouping; unknown commands/menus retain fallback destinations. See RIBBON_LAYOUT.md for the exact mapping. Other lazy submenus remain demand-driven. Form Align/Make Same Size and Insert Add are expanded into direct commands through js/native-toolbar-context.js. The bridge uses the trusted native producer's own Function constructor/realm with only showContextMenu shadowed; async callbacks close over that sink instead of changing the global hook. Insert invokes the actual showContextMenuAddComponent producer; Format invokes native hover producers. Context inheritance and descriptors are retained. Known Form child actions reuse the original toolbar source nodes. A producer that cannot be isolated (bound function/private lexical dependency/API change) retains its parent fallback, and callbacks after restoration are ignored. Active expanded groups refresh on the existing menu epoch; inactive captured groups keep their descriptors/state authority. It preserves command IDs, alternatives, native context expressions, enabled/checked states, combo options and original actions. Native toolbar command proxies dispatch the ordinary mouse sequence to the original nodes; build/zoom/grid controls retain their original nodes and handlers.

The live adapter observes current sources and the selected editor through a bounded 400ms scan, captures the active menu no more than once per second, and reconciles late toolbar/menu contributions without a whitelist of future commands. It supports synchronous/lazy submenus and the native asynchronous Add-ins list. Unsupported native structure restores Classic while retaining the requested mode for persistence. Private-API structural compatibility is not guaranteed for arbitrary future betas.

The fullscreen File view sits inside the IDE window. Quick access is hidden immediately while File is open, then restored before focus return. File uses a vertical rail and vertical task lists backed by native descriptors. Info shows the actual project name with settings/references tasks. Native Help now resides under File > Help; native Help menu opening is intercepted to this page. Save and Exit restore/close Backstage before native dispatch. Options opens the shared page containing IDE Options, language and keyboard shortcuts; its commands close File before native dispatch. The workspace/designer and floating panels are hidden/inert with their previous accessibility values restored on close, action, mode change or unload. Stable signatures retain focus across refreshes. Loaded-add-in information moves into its Add-ins section; other add-ins' toolbar contributions remain on the Add-ins ribbon tab. BETA 1044 has no functional native enable/disable action: its loaded-add-in actions call notSupportedMenuOption. Those entries are displayed disabled with an explanation, and real enablement remains roadmap work.

Save/Undo/Redo/Play/Pause/Stop use the former menu space in rootMenu1Inner, which is the custom title bar when Show real OS titlebar is off and the row above the ribbon when it is on. Window controls and title-drag handlers remain owned by the IDE. File Escape/back returns focus; tab arrow navigation and Ctrl+F1 collapse are handled locally. Undo/Redo and the three main execution controls are omitted from content groups. Current groups use explicit large command roles and three stacked rows with horizontal overflow; complete Office adaptive collapse/keytips and visual acceptance remain open.

The original 1.2.0.1 base geometry uses central CSS variables (the current full-mode override is 73px high, with 23px stacked rows and 7px top padding): command area 100px maximum and separate tab strip 26px maximum; full-size button minimum/standard width 50px, maximum width 86px and fixed height 76px. Border-box sizing includes padding/borders. Three stacked 24px rows with two 2px gaps also occupy 76px. Compact group captions and two-line large-button labels keep that vertical budget; complete captions remain in tooltips. Quick-access, Backstage and popup controls retain their own dimensions. These are Shane's explicit composition values, supported by his Office spacing screenshot, rather than asserted WinUI Ribbon template values.

The 1.2.0.2 presentation separates short known-command/selector captions from full native help/shortcut tooltips. This mapping only refines labels; discovery and dispatch remain native and unknown contributions remain accessible. Stacked captions use single-line ellipsis, and group padding/column gaps are compact. Essential toolbar CSS carries the existing simplified-toolbar Fluent shadow4 elevation and 8px card corners; it does not substitute a new theme palette.

## Theme and icon ownership

css/ide-toolbar.css is essential presentation, independent of the optional theme stylesheet. Surface/foreground colors follow the active IDE theme, including standard and third-party themes. The tab strip uses themeMenuBackColor/themeMenuForeColor separately from the command card; selected/hover tabs stay transparent with accent/grey underline indicators. The command card owns the corners; its shadow/bottom border are enabled only by the theme-derived tbui3-ribbon-winui shell class. syncRibbonTheme reconciles that class on creation and the existing timer without rebuilding controls. The toolbar uses the existing color-card / CardBackgroundFillColorDefault token when available, otherwise themeToolbarBackground; foreground follows color-text / themeGeneralTextColor. Quick access retains the menu/titlebar foreground, and popups use the opaque application flyout/general surface with the application foreground, avoiding native context-menu resources which are intentionally light in the supplied dark theme. Essential light/dark SubtleFillColorSecondary/Tertiary alpha fills use the same pinned WinUI resources as winui3-ide.css, independently of the optional styling switch; these are interaction effects rather than a replacement palette. WinUI 3 supplies the visual language; Office supplies the ribbon organization. The existing 19 Fluent SVGs are centered as 28px artwork in 32px full-size canvases / 16px small command canvases. icons/ribbon.json adds 18 MIT Fluent SVGs from pinned Microsoft source for missing glyphs; the builder embeds them into the same masked-currentColor map. Explicit requested icon assignments take priority; native codicons and original source images remain authoritative for unlisted commands. Text-only add-ins/future commands get a Fluent fallback instead of an empty or hidden icon. Unlisted native designer glyphs and other add-ins' images are retained. The requested Global Search icon overrides its contributed image. No Office icons or additional runtime icon-library dependency is introduced.

WinUI3IdeCss contains 290 generated rules, including neutral Light caption handling. Its media state and panel-title normalization are controlled solely by the original additional-styling switch. Essential toolbar presentation requires neither that switch nor an included theme name. The renderer reads the switch for the theme-scoped window insets and accent synchronization.

The Grid options retain native nodes/events and use the shared fieldset foreground, themed number-input fill/border and a single-column flyout layout. The BETA 1044 native field classes force background:white !important; a single scoped background override consumes the themed fill token with normal/hover/focus mappings. This is an explicit host-integration exception, analogous to the existing native visibility rules, not a generic override layer. All full-size buttons use a stretched single grid column and font-measured two-line whole-word width, bounded by 50px/86px. Their top-aligned rows budget a 32px glyph canvas, 4px gap, 28px two-line caption, 2px gap and 8px optional chevron plus 1px borders: exactly 76px. The 100px card's base geometry has 4px padding; the current full-mode override uses 7px and a 73px command area. Dividers are 89px. Full Grid uses its labeled toggle with original inline options; Simplified reparents those same nodes into the options flyout beside the icon-only toggle. Separate iconOnly and simplifiedIconOnly metadata restores full labels on every presentation change. Configuration and Zoom retain hidden accessible captions. Compact chevrons are centered at the right. File Back wraps the existing left-arrow mask in a 26px circular outline inside a 40px icon button, with an accessible label/tooltip; these Office-specific composition dimensions are not asserted as a WinUI control template.

## Dropdown layer ownership

Native BETA 1044 windowed designer controls add WINDOWED_CONTROLS_ZINDEX_OFFSET=1e6, and selection grabbers use 99,999,999. The earlier 100,001 dropdown layer could paint underneath them. Dropdowns remain body-owned and request auto showPopover promotion when available, which places them in the browser top layer rather than the designer stacking tree. CSS clears user-agent popover centering/inset defaults. The legacy path uses the maximum signed CSS z-index at the end of body; it does not alter or hide designer objects. Feature absence or a failed promotion removes the popover attribute and retains that fallback. Source: [HTML popover standard](https://html.spec.whatwg.org/multipage/popover.html) and [Chrome popover overview](https://developer.chrome.com/blog/introducing-popover-api/).

Popovers now use auto mode for browser light-dismiss. Window-level capture listeners handle both pointerdown and mousedown before native document handlers, dismissing outside the popup/its anchor without cancelling the original event. Browser toggle-to-closed and window blur also remove owned UI; clicking the same dropdown toggles it closed. Popup anchors expose aria-expanded. Closing invokes hidePopover when promoted, removes owned content/bindings and clears anchor state. Escape, commands, File navigation, mode changes and unload share that cleanup. Auto popovers retain nonmodal keyboard behavior while adding native browser light-dismiss.

## Editor and native control state

The native bridge reads openEditors.selectedEditorNode and its native CodeEditor/UIDesigner type. The adapter records identity and type, switching Code/Form only when either changes, so manual tab choices persist while the editor remains stable. Other document types do not force a tab. File defers observation until exit. No native editor activation method is replaced.

The visible Zoom caption is a clipped accessible label, not a second visual row; the original selector is still parked/restored. Form's Grid command proxies the original menuBarGrid handler/checked state. Its canonical optionGridShow checkbox remains in the native body and is hidden only by a replacement-fieldset selector while the toggle exists. Native toggle/settings code still updates it; Classic restoration removes the selector scope and preserves the value/events.

## Theme transition reconciliation (1.3.0.4)

The BETA 1044 theme menu calls changedIdeOptions and notifyChangedTheme, but both old and current IDE Options save paths omit the notification. The options timer compares Host.Themes.ActiveThemeName to LastThemeName each second, independently of preference dirtiness. InstallOption preserves an already initialized page-side Enabled/dirty value, and ApplyStyle assigns media before attachment. A separate MutationObserver watches root theme properties and body mode: it checks the actual getThemeName, removes optional CSS immediately on departure, restores original titles and records the actual activeThemeData property set. On a named transition it removes previously recorded variables absent from the new palette only if value/priority are still unchanged. It does not replace current native values. Both page observers disconnect on unload.

The styling switch controls WinUI3IdeCss, sentence-case titles and the optional window insets. Native page management and essential Hybrid/Ribbon presentation remain independent. The included light/dark optional CSS now defines color-menu-shadow using the existing Fluent shadow4 effect. Native context menus/submenus and replacement dropdowns consume it; turning additional styling off removes that token/effect. File uses the general application foreground rather than the native dialog foreground, since Native Dark deliberately has light dialogs. The rail extends 32px upward through the hidden quick-access area without covering title controls or changing the native drag handlers.

## Theme files and styling reference

The standalone theme generator is `tools/build-themes.mjs`; its output is in themes/. Generate instead of hand-editing managed theme payloads. The theme files inherit dark/light and override native CSS properties from Microsoft's Common_themeresources_any.xaml. Static fallback accents are #60CDFF (Dark) and #005FB8 (Light); optional styling supplies the live system palette, Dark Light2/Light3 and Light Dark1/Dark2, while native selection uses the base accent. Semantic and inherited syntax colors remain unchanged. The standalone theme baseline requires BETA 1033 or later for dialog/panel properties; this is not add-in compatibility.

The native .theme parser uses Name: value; declarations, including inherits, and produces --themeName variables; !important is recognized. Historically the parser splits on semicolon followed by space/newline and colon-space; missing semicolons can drop adjacent properties. Verify on each new beta against native Dark/Light and actual IDE stylesheets. The loader reads installation and AppData themes. Preserve customized files. Reload from disk before selecting a newly copied standalone theme.

Optional styling covers native hard-coded surfaces beyond .theme reach: dialog buttons and progress, menu/status hover, flyouts, editor tabs, dropdowns, check/radio controls, scrollbars, tooltips, settings navigation and fields, reference/warning lists, panel headers and trees. Property sheet inputs are not generally restyled. Additional styling persists in HKCU\Software\VB and VBA Program Settings\WinUI3IdeStyle\Options, Enabled; the toolbar setting is independent. Style injection via the hidden ToolWindow's ownerDocument/defaultView bridge is a private host integration; ToolWindow.ApplyCss alone reaches only its shadow root. Preserve the host's state and cleanup. Source: tbUI3IDE/css/winui3-ide.css, with generated icon CSS. Run node tbIDE/tools/build-toolbar-icons.mjs and node tbIDE/tools/build-addin-css.mjs as applicable, then patch/regenerate the canonical project using the established tooling. Do not edit generated WinUI3IdeCss.twin by hand.

Native limitations to recheck by beta: fixed caption artwork and modal title colors, fixed property/category/Options text and edges, front-page search/card/version-badge colors, missing native theme properties for fonts/tab shapes/heights, and no native theme-based Mica/acrylic. Standalone themes retain host defaults where they cannot override a property. See the current ROADMAP and validation evidence for follow-ups rather than assuming a historical limitation still applies unchanged.
